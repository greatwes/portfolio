Global Rate Limiter

Source ↗

Rate limiting as a service, built the way a systems-design interview wishes real code looked. Every token-bucket decision runs inside a single atomic Redis Lua script — no distributed locks, no over-admission under concurrency — while a separate, eventually-consistent analytics pipeline streams usage into TimescaleDB for a live client dashboard. Every dependency failure has a configured, deliberate degradation path.

  • Sub-5ms p99 decision latency, one Redis round trip per check
  • Stateless instances — any number of replicas enforce one global limit
  • 43 tests run against the real production Lua script with zero infrastructure

AI Interview Screening Pipeline

Source ↗

A three-stage AI recruiting funnel in n8n: an LLM scores resumes against the job description, a voice AI agent conducts and transcribes a live phone screening interview, and a third LLM call compares every remaining candidate head-to-head to pick the best N — not just rank them independently.

Payment Webhook Reconciliation

Source ↗

Reconciles a payment provider's transactions two ways at once: a signature-verified real-time webhook for speed, and a scheduled statement pull as a safety net for whatever the webhook missed — both writing through the same idempotent upsert so neither path can create a duplicate.

  • HMAC-SHA512 verified over the raw body, compared with a timing-safe check
  • Dual push + pull design: webhook speed, scheduled-pull correctness guarantee
  • Upserts matched on the provider's own transaction reference

02 About

I work where clean software design meets operational reality: devices that can't be trusted to send the same batch twice, automation platforms with no SQL binding parameters, and spreadsheets standing in for a database because that's the tool everyone already knows.

The common thread across these projects is defensive engineering — idempotent writes, verified delivery instead of assumed delivery, and tests that run without ever touching real infrastructure. I'd rather a system fail loudly in a test than quietly in production.

Currently focused on

  • Backend services & APIs (Python / FastAPI)
  • Data pipelines & warehouse integration (Snowflake, Dataiku, n8n)
  • Automation tooling for teams without a dedicated dev stack
  • Reliability — idempotency, graceful degradation, verified delivery
